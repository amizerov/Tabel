# Табель СКУД

Программа заполняет табель подрядчика по событиям системы контроля доступа (СКУД), а затем сравнивает исходные и рассчитанные часы.

## Быстрый порядок работы

1. На шаге **«Заполнение табеля по СКУД»** выберите исходный табель подрядчика.
2. Выберите выгрузку СКУД.
3. Нажмите **«Обработать»**.
4. После успешной обработки программа автоматически откроет шаг **«Сравнение табелей»** и подставит нужные файлы.
5. Нажмите **«Сравнить»**.

Вернуться к первому шагу можно кнопкой **«← Заполнение»**. Повторно выбрать файлы можно кнопками **«Выбрать...»**.

## Какие файлы нужны

### Исходный табель подрядчика

Файл Excel формата `.xlsx`, содержащий:

- колонку ФИО;
- строку с датами или номерами дней месяца;
- строки сотрудников;
- заявленные часы смен.

Распознаются заголовки `ФИО`, `Ф.И.О.`, `Ф. И. О.`, `Фамилия И.О.` и `Фамилия Имя Отчество`.

Заполненный табель и файл результата сравнения нельзя использовать как исходный табель. Новые файлы программы получают скрытую внутреннюю метку. Старые файлы сравнения дополнительно распознаются по комментариям и цветовой разметке.

### Выгрузка СКУД

Файл Excel формата `.xlsx`. На одном из листов должны находиться колонки:

- `Дата записи`;
- `Персона`;
- `Сообщение`.

При выборе выгрузки проверяются только эти колонки. Цвета, комментарии и внутренние метки не учитываются.

## Результаты заполнения

Рядом с исходным табелем создаются:

- `<имя табеля>_заполнен.xlsx`;
- `<имя табеля>_протокол.txt`.

Программа обрабатывает только даты, на которые в исходном табеле заявлена смена.

## Расчёт часов по СКУД

Для каждого сотрудника и дня анализируются разрешённые события прохода.

- При наличии входа и выхода рассчитывается фактическая продолжительность смены по действующим правилам округления и вычета перерыва.
- Если найдена только одна разрешённая отметка, применяется правило одной отметки. Обычно устанавливается `2` часа.
- Если разрешённых отметок нет, отсутствие данных не считается нулём часов.
- Если сотрудник не найден или сопоставление ФИО неоднозначно, программа сохраняет отдельный специальный статус.

## Сопоставление сотрудников

Сначала используется полное нормализованное ФИО. Если полного совпадения нет, применяется краткий ключ из фамилии и первой буквы имени.

Сомнительное или неоднозначное совпадение автоматически не принимается и требует ручной проверки.

## Сравнение табелей

После заполнения сравниваются заявленные часы исходного табеля и рассчитанные часы СКУД.

### Часы совпадают

- Значение не изменяется.
- Заливка не добавляется.
- Комментарий о сравнении не создаётся.

### По СКУД часов больше заявленного

- В итоговом файле остаются заявленные часы.
- Обычная цветовая заливка не добавляется.
- В комментарии указываются заявленные часы, часы СКУД и принятое итоговое значение.

### По СКУД часов меньше заявленного

- В итоговом файле записываются фактические часы СКУД.
- Ячейка выделяется жёлтым.
- Любое уменьшение выделяется независимо от величины расхождения.
- В комментарии указывается величина уменьшения.

### Данных СКУД нет

- Пустые данные не преобразуются в `0`.
- Ячейка сохраняет красный специальный статус.
- В комментарии указывается причина: нет разрешённых отметок или сотрудник не найден.

## Значение цветов

- **Без заливки** — часы совпадают либо СКУД показывает больше заявленного, и оставлены заявленные часы.
- **Жёлтый** — по СКУД часов меньше заявленного.
- **Сине-голубой** — за день найдена только одна разрешённая отметка СКУД.
- **Светло-красный / розовый** — при заявленной смене нет подтверждающих данных СКУД либо сотрудник не найден.
- **Оранжевый** — неоднозначное сопоставление ФИО.
- **Светло-зелёный** — цвет старых версий сравнения; в новых файлах не используется.

Специальные красный, голубой и оранжевый статусы имеют приоритет и не заменяются обычной жёлтой заливкой сравнения.

## Комментарии Excel

Для любого отклонения или специальной ситуации создаётся комментарий. Если в заполненном табеле уже был комментарий, он не удаляется: информация о сравнении добавляется ниже отдельным блоком `Сравнение:`.

## Результаты сравнения

Рядом с исходным табелем создаются:

- `<имя табеля>_сравнение.xlsx`;
- `<имя табеля>_протокол_сравнения.txt`.

Протокол содержит ФИО, дату, заявленные часы, часы СКУД, итоговое значение, разницу и статус.

## Проверка выбранных файлов

Проверка выполняется сразу после выбора файла. Неверный файл не записывается в поле, а кнопка действия остаётся недоступной.

- Для табеля проверяются структура, ФИО, даты и внутренний тип книги.
- Для СКУД проверяются обязательные колонки.
- Один файл нельзя одновременно использовать как исходный и заполненный табель.

## Журнал и индикатор выполнения

Нижняя часть окна показывает текущий этап, процент выполнения и подробный журнал. При ошибке в журнале сохраняется её причина.

## Горячие клавиши

- `F1` — открыть эту справку.
- `Esc` — закрыть окно справки.
