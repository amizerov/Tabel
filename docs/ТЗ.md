## 1. Назначение разработки

Необходимо разработать/доработать программу для автоматического заполнения табеля подрядчика на основании выгрузки СКУД, а также отдельный режим сравнения исходного табеля подрядчика с заполненным табелем.

Программа должна работать с Excel-файлами формата `.xlsx`. Названия файлов могут отличаться, поэтому программа не должна быть жёстко привязана к конкретным именам файлов.

Операции программы:

1. **Заполнить табель подрядчика по данным СКУД.**
2. **Сравнить исходный табель подрядчика с заполненным табелем и сформировать файл сравнения.**

Исходные файлы не должны перезаписываться ни в одном режиме работы.

Основная задача — исключить ручной перенос часов из СКУД в Excel-табель, сохранить внешний вид исходного файла и получить диагностически понятный результат:

- кто найден и сопоставлен;
- кто не найден;
- какие ФИО сопоставлены неоднозначно;
- по каким дням рассчитаны часы;
- какие события СКУД не использованы в расчёте;
- где есть расхождения между исходным табелем и рассчитанными часами;
- какие строки и даты требуют ручной проверки.

## 2. Термины и результат работы программы

| Термин | Описание |
|---|---|
| Исходный табель подрядчика | Excel-файл подрядчика, выбранный пользователем как исходный табель для заполнения или сравнения. |
| Файл СКУД | Excel-файл с выгрузкой проходов сотрудников через систему контроля и управления доступом. |
| Заполненный табель | Новый Excel-файл, созданный на основе исходного табеля и дополненный рассчитанными часами по данным СКУД. |
| Файл сравнения | Новый Excel-файл с результатами сравнения исходного и заполненного табеля, выделением отличий и переносом диагностических примечаний. |
| Дневная ячейка | Ячейка табеля на пересечении строки сотрудника и колонки конкретной даты/дня месяца. |
| Период табеля | Набор дат, найденных в табеле по строке дат или номерам дней месяца. |
| Разрешенная запись СКУД | Событие из колонки `Сообщение`, соответствующее разрешённому входу или выходу. |
| Проблемное сообщение СКУД | Сообщение о запрете, повторном проходе, сбое, заблокированном пропуске или иной нештатной ситуации. Такие сообщения не участвуют в расчёте часов, не создают подсветку и примечания в Excel и фиксируются только в протоколе обработки. |

## 3. Общая схема работы

### 3.1. Заполнение табеля

Пользователь запускает программу и выполняет следующие действия:

1. Выбирает файл **«Табель подрядчика»**.  
   Пример: `табель подрядчика.xlsx`.
2. Выбирает файл **«Выгрузка СКУД»**.  
   Пример: `СКУД СТРОЙМОНТАЖ 01.02.-28.02.2026.xlsx`.
3. Нажимает кнопку запуска обработки.
4. Программа создаёт копию исходного табеля.
5. В копии табеля программа заполняет дневные ячейки рассчитанными часами по данным СКУД.
6. Создаётся файл заполненного табеля.
7. После завершения программа показывает журнал выполнения и путь к созданному файлу.

Имя файла заполненного табеля:

```text
<имя исходного табеля>_заполнен.xlsx
```

Пример:

```text
табель подрядчика_заполнен.xlsx
```

### 3.2. Сравнение табелей

Пользователь запускает режим сравнения и выполняет следующие действия:

1. Выбирает исходный табель подрядчика.
2. Выбирает заполненный табель подрядчика.
3. Нажимает кнопку запуска сравнения.
4. Программа создаёт файл сравнения на базе заполненного табеля.
5. В файл сравнения переносятся рассчитанные часы, диагностические выделения и примечания.
6. Поверх копии применяются результаты сравнения с исходным табелем.
7. После завершения программа показывает журнал выполнения и путь к созданному файлу сравнения.

Имя файла сравнения:

```text
<имя исходного табеля>_сравнение.xlsx
```

Пример:

```text
табель подрядчика_сравнение.xlsx
```

## 4. Требования к входному файлу «Табель подрядчика»

Файл содержит табель подрядчика в формате Excel `.xlsx`.

Программа не должна быть жёстко привязана к фиксированным номерам строк и колонок. Структура табеля должна определяться автоматически по содержимому листа.

В типовом приложенном файле табеля:

- строка 1 содержит общее наименование табеля;
- строка 2 содержит дополнительную служебную информацию, например подразделение или группу;
- строка 3 содержит заголовки колонок, включая `ФИО`, дни недели и `Итого часов`;
- строка 4 содержит даты месяца;
- данные сотрудников начинаются со строки 5.

Указанные номера строк являются примером текущего шаблона, а не жёстким правилом.

Обязательные требования:

- колонка с ФИО определяется по заголовку `ФИО`;
- строка заголовков определяется по наличию заголовка `ФИО`;
- строка дат определяется как строка, содержащая даты месяца или номера дней месяца и расположенная рядом со строкой заголовков, обычно непосредственно под ней;
- строки сотрудников начинаются после строки дат;
- дневные ячейки определяются по найденным датам или номерам дней месяца;
- колонка `Итого часов`, если она есть, определяется по заголовку `Итого часов` и должна сохраняться;
- программа не должна перезаписывать формулы итогов, если они присутствуют.

Программа не должна быть жёстко привязана к координатам вроде `B`, `D:AH`, `AF` или `AI`. Эти координаты могут использоваться только как пример конкретного шаблона.

Рекомендуемое правило поиска структуры:

1. Просмотреть первые 10–15 строк листа.
2. Найти строку, содержащую заголовок `ФИО`.
3. Найти строку дат: это строка, расположенная рядом со строкой заголовков, обычно следующая строка, и содержащая Excel-даты или номера дней месяца.
4. Определить дневные колонки по найденным датам или номерам дней.
5. Считать, что строки сотрудников начинаются со строки, следующей после строки дат.

Если строка с заголовком `ФИО` не найдена, программа должна выдать ошибку:

```text
В табеле не найдена колонка ФИО.
```

Если строка дат не найдена, программа должна выдать ошибку:

```text
В табеле не найдена строка с датами или номерами дней месяца.
```

## 5. Определение дневных колонок в табеле

Дневные колонки должны определяться по фактически найденным значениям дат/дней, а не по заранее заданному количеству дней месяца.

Программа должна поддерживать два варианта указания дат в табеле:

1. **Полноценные Excel-даты**: например `01.02.2026`, `02.02.2026`, `03.02.2026`.
2. **Номера дней месяца**: например `1`, `2`, `3`, ..., `28`, `29`, `30`, `31`.

Если в табеле указаны полноценные даты, соответствие с записями СКУД строится по этим датам.

Важно: если в ячейке хранится полноценная Excel-дата, но формат отображения показывает только номер дня месяца, например `1`, `2`, `3`, программа должна обрабатывать такую ячейку именно как дату, а не как простое число.

Если в табеле указаны только номера дней месяца, месяц и год определяются по датам из файла СКУД.

Если в файле СКУД найдено несколько месяцев и невозможно однозначно определить месяц табеля, программа должна остановить обработку и выдать ошибку с просьбой использовать табель с полными датами или уточнить период.

Количество дней месяца определяется по самому табелю: для февраля может быть 28 или 29 дней, для апреля 30 дней, для мая 31 день и т.д.

## 6. Требования к входному файлу «Выгрузка СКУД»

Файл содержит данные проходов сотрудников через СКУД.

Обязательные колонки должны определяться по названиям, а не по фиксированным номерам колонок.

| Колонка | Назначение | Пример расположения |
|---|---|---|
| `Дата записи` | Дата и время события прохода. | Колонка A |
| `Персона` | ФИО сотрудника в выгрузке СКУД. | Колонка C |
| `Сообщение` | Тип события: вход, выход, запрет, повторный вход/выход, сбой и т.п. | Колонка D |

Если файл СКУД содержит несколько листов, программа должна автоматически определить рабочий лист по наличию обязательных колонок:

- `Дата записи`;
- `Персона`;
- `Сообщение`.

Листы, на которых отсутствует хотя бы одна из обязательных колонок, должны игнорироваться.

Если ни на одном листе не найден полный набор обязательных колонок, программа должна остановить обработку и выдать понятную ошибку:

```text
В файле СКУД не найден лист с обязательными колонками: Дата записи, Персона, Сообщение.
```

Колонка `Дата записи` должна разбираться как дата и время. Колонка `Персона` должна использоваться для сопоставления ФИО. Колонка `Сообщение` является обязательной и влияет на расчёт часов и диагностическое выделение ячеек.

Названия колонок должны сравниваться без учёта регистра, лишних пробелов и неразрывных пробелов.

## 7. Правила сопоставления ФИО

Для каждой строки табеля подрядчика программа берёт значение из колонки `ФИО` и ищет соответствующего сотрудника в колонке `Персона` файла СКУД.

### 7.1. Нормализация ФИО

Перед сравнением ФИО необходимо нормализовать:

- убрать начальные и конечные пробелы;
- заменить неразрывные пробелы обычными;
- заменить последовательности нескольких пробелов одним пробелом;
- привести текст к одному регистру;
- заменить `ё` на `е`;
- убрать точки после инициалов;
- игнорировать различия в количестве пробелов;
- привести `Фамилия И.О.` и `Фамилия Имя Отчество` к сопоставимому виду.

### 7.2. Ключ поиска `Фамилия + первая буква имени`

Если точное совпадение полного ФИО не найдено, программа формирует ключ поиска:

```text
Фамилия + первая буква имени
```

Пример:

```text
Удовиченко Александр Павлович -> Удовиченко А
Иванов С.П.                   -> Иванов С
```

Ключ должен формироваться как для ФИО из табеля, так и для значения из колонки `Персона` файла СКУД.

Поиск только по фамилии не допускается как достаточное условие сопоставления.

### 7.3. Порядок поиска

1. Сначала искать точное совпадение полного ФИО после нормализации.
2. Если точного совпадения нет, искать по ключу `Фамилия + первая буква имени`.
3. Если по ключу найден ровно один сотрудник в СКУД, использовать его.
4. Если совпадений нет, считать ФИО не найденным.
5. Если по ключу найдено несколько сотрудников и точного совпадения полного ФИО нет, считать ФИО неоднозначным.
6. Если невозможно сформировать ключ, например в табеле указана только фамилия без имени, считать ФИО не найденным или вынести в протокол как требующее ручной проверки.

## 8. Действия при ненайденном или неоднозначном ФИО

| Ситуация | Действия программы |
|---|---|
| ФИО не найдено в СКУД | Часы по сотруднику не заполняются. Ячейка ФИО в выходном файле выделяется светло-красным цветом. К ячейке ФИО добавляется примечание: `ФИО не найдено в выгрузке СКУД. Ключ поиска: <Фамилия И>`. |
| ФИО найдено неоднозначно | Часы по сотруднику не заполняются. Ячейка ФИО выделяется оранжевым цветом. К ячейке ФИО добавляется примечание: `Неоднозначное совпадение в СКУД. Ключ поиска: <Фамилия И>. Найденные варианты: ...`. |
| По сопоставленному сотруднику нет записей СКУД за отдельные даты | Дневные ячейки без записей остаются пустыми. ФИО сотрудника выделяется отдельным диагностическим цветом, например голубым, и в примечании к ФИО указывается, что по сотруднику есть даты без записей СКУД. |
| По сопоставленному сотруднику нет ни одной записи СКУД за весь период табеля | Все дневные ячейки остаются пустыми. ФИО выделяется диагностическим цветом и получает примечание: `По сотруднику нет записей СКУД за период табеля`. |

Если требуется исключать выходные или праздничные дни, это должно быть задано отдельным правилом. В текущем ТЗ такие дни не исключаются автоматически.

Исходный файл табеля подрядчика не изменяется. Все выделения и примечания выполняются только в выходном файле.

В режиме сравнения цвет и комментарий по ненайденному или неоднозначному ФИО должны переноситься в файл сравнения. Это обязательное требование.

## 9. Алгоритм расчёта часов по данным СКУД

После сопоставления сотрудника программа анализирует все записи СКУД по этому сотруднику.

Данные группируются по схеме:

```text
Сотрудник -> Дата -> Список проходов за дату
```

Для каждой пары `сотрудник + дата` формируется список событий за календарный день. События сортируются по времени.

### 9.1. Использование колонки `Сообщение`

Для расчёта времени используются события СКУД из колонки `Сообщение`. Текст сообщения должен сравниваться без учёта регистра, лишних пробелов и различий `е`/`ё`.

Например, `запрещен` и `запрещён` должны распознаваться как однотипные сообщения.

| Тип сообщения | Как обрабатывать |
|---|---|
| `вход разрешен` | Учитывать как разрешенную отметку входа. |
| `выход разрешен` | Учитывать как разрешенную отметку выхода. |
| `ПОВТОРНЫЙ вход запрещен` / `ПОВТОРНЫЙ вход запрещён` | Не использовать для расчёта часов. Дневную ячейку не выделять, значение не менять, примечание в Excel не добавлять. Записать ситуацию в протокол. |
| `ПОВТОРНЫЙ выход запрещен` / `ПОВТОРНЫЙ выход запрещён` | Не использовать для расчёта часов. Дневную ячейку не выделять, значение не менять, примечание в Excel не добавлять. Записать ситуацию в протокол. |
| Запрет входа, заблокированный пропуск, сбой и другие проблемные сообщения | Не использовать для расчёта часов. Не выделять дневную ячейку, не добавлять примечание в Excel. Записать сообщение в протокол. |

Запрещающие, ошибочные и служебные сообщения:

- `Выход запрещен` / `Выход запрещён`;
- сообщения, начинающиеся со слова `Запрещено`;
- сообщения о заблокированном или неактуальном пропуске;
- сообщения о несогласованной заявке;
- сообщения о несовпадении даты входа;
- сбои и иные проблемные сообщения.

Такие сообщения не используются для расчёта часов. Соответствующая дневная ячейка не выделяется как требующая ручной проверки, примечание в Excel не добавляется, значение ячейки не меняется. Ситуация добавляется только в протокол обработки.

Для расчёта часов по дню используются только разрешенные входы и выходы. Проблемные сообщения должны попадать в протокол обработки с указанием сотрудника, даты, количества проблемных сообщений и их текстов. Если за день есть разрешённые и проблемные сообщения одновременно, расчёт выполняется только по разрешённым событиям, а проблемные сообщения не влияют на рассчитанное значение.

### 9.2. Если за дату есть повторный вход/выход запрещен или иное проблемное сообщение

Если за дату у сотрудника найдено сообщение `ПОВТОРНЫЙ вход запрещен`, `ПОВТОРНЫЙ вход запрещён`, `ПОВТОРНЫЙ выход запрещен`, `ПОВТОРНЫЙ выход запрещён` или иное проблемное/запрещающее сообщение, оно считается диагностическим событием СКУД и не участвует в расчёте часов.

Требования:

- проблемное сообщение не используется при определении первой и последней разрешённой отметки за дату;
- дневная ячейка не выделяется цветом из-за такого сообщения;
- значение дневной ячейки не изменяется из-за такого сообщения;
- примечание в Excel по такому сообщению не добавляется;
- ситуация записывается только в протокол обработки;
- если за дату есть разрешённые входы/выходы, часы рассчитываются только по разрешённым событиям;
- если за дату есть только проблемные/запрещающие сообщения и нет разрешённых входов/выходов, значение дневной ячейки не меняется и примечание не добавляется.

### 9.3. Если за дату есть две и более разрешенные записи

Если за дату есть две и более разрешенные записи `вход разрешен` / `выход разрешен`, расчёт выполняется по первой и последней разрешенной отметке за дату:

```text
первая разрешенная отметка за дату;
последняя разрешенная отметка за дату;
длительность = последнее время - первое время - 1 час.
```

Если после вычитания 1 часа результат меньше 0, в табель записывается `0`.

Округление выполняется не обычным «округлением вверх», а по правилу минутного порога:

| Условие после вычитания 1 часа | Что записывать |
|---|---|
| Минутная часть меньше 50 минут | Записать только полные часы без увеличения. |
| Минутная часть больше или равна 50 минутам | Увеличить количество часов на 1. |

Пример 1:

```text
Первый проход: 09:00
Последний проход: 18:10
18:10 - 09:00 = 9 часов 10 минут
9 часов 10 минут - 1 час = 8 часов 10 минут
10 минут < 50 минут -> в табель записывается 8
```

Пример 2:

```text
Первый проход: 09:00
Последний проход: 18:50
18:50 - 09:00 = 9 часов 50 минут
9 часов 50 минут - 1 час = 8 часов 50 минут
50 минут >= 50 минут -> в табель записывается 9
```

Пример 3:

```text
Первый проход: 09:00
Последний проход: 09:30
09:30 - 09:00 = 30 минут
30 минут - 1 час = -30 минут
Результат меньше 0 -> в табель записывается 0
```

### 9.4. Если за дату есть только одна разрешенная запись

Если по сотруднику за конкретную дату найдена только одна разрешенная запись СКУД, то в соответствующую дневную ячейку табеля записывается значение `2`.

Такая ячейка должна быть выделена отдельным цветом, отличным от цветов для ненайденных ФИО, неоднозначных ФИО, повторных входов/выходов и результатов сравнения. Например, можно использовать светло-синий цвет.

В протоколе желательно указать:

```text
Одна разрешенная запись СКУД за день. Установлено 2 часа.
```

### 9.5. Если за дату нет разрешенных записей

Если по сотруднику за конкретную дату нет разрешенных записей СКУД, дневная ячейка табеля за этот день остаётся пустой.

При этом ФИО сотрудника должно получить диагностическое выделение, если по сотруднику есть даты без записей СКУД. В примечании к ФИО желательно указать количество или список таких дат.

### 9.6. Внутридневные события

Если в течение дня есть несколько входов и выходов, текущая версия не требует полноценного суммирования интервалов.

Базовое правило:

```text
берётся первое и последнее допустимое событие дня
```

Промежуточные события сохраняются в протоколе для диагностики, но не меняют расчёт, если отдельно не будет принято иное решение.

### 9.7. Ночные смены

Если последнее событие календарного дня раньше первого события или есть признаки перехода через полночь, строка считается требующей ручной проверки.

В базовой версии ночные смены автоматически не рассчитываются, если это не предусмотрено отдельной настройкой.

### 9.8. Ограничения расчёта

Программа не должна рассчитывать часы по строкам:

- без ФИО;
- без сопоставления с СКУД;
- с неоднозначным сопоставлением;
- с некорректной датой;
- с событиями, не прошедшими фильтр по колонке `Сообщение`.

Проблемные сообщения СКУД сами по себе не являются основанием для запрета расчёта по дню, если в этот день есть две и более разрешённые записи. В этом случае расчёт выполняется только по разрешённым событиям, а проблемные сообщения фиксируются в протоколе.

## 10. Запись результата и протокол обработки

### 10.1. Создание заполненного табеля

Программа создаёт новый файл на основе исходного табеля подрядчика.

Имя выходного файла формируется так:

```text
<имя исходного табеля>_заполнен.xlsx
```

В выходной файл должны быть скопированы:

- вся структура исходного табеля;
- форматирование;
- объединенные ячейки;
- формулы;
- ширины колонок;
- высоты строк;
- стили ячеек;
- примечания, если они уже были в исходном файле.

Программа заполняет только дневные ячейки часов и диагностические примечания/выделения, связанные с расчётом времени или сопоставлением ФИО. Запрещающие и проблемные сообщения СКУД не создают примечания и подсветку в дневных ячейках. Остальные данные исходного табеля не должны изменяться.

### 10.2. Итоговая колонка

Если колонка `Итого часов` найдена, программа может пересчитать итог по строке сотрудника:

```text
итог = сумма часов по дневным колонкам
```

Если в итоговой ячейке уже есть формула, программа не должна перезаписывать формулу, если это не включено отдельной настройкой.

Если итоговая колонка не найдена, дневные часы всё равно заполняются, а в протокол записывается предупреждение.

### 10.3. Протокол обработки

После завершения обработки программа должна показать пользователю краткий отчет:

- сколько сотрудников найдено в табеле;
- сколько сотрудников успешно сопоставлено со СКУД;
- сколько ФИО не найдено;
- сколько ФИО найдено неоднозначно;
- сколько сотрудников имеют даты без записей СКУД;
- сколько дневных ячеек заполнено часами;
- сколько ячеек выделено по диагностическим правилам, связанным с расчётом времени или сопоставлением ФИО;
- путь к созданному файлу.

Желательно также создать отдельный лист `Протокол` в выходном файле.

На листе `Протокол` указать:

- дату и время обработки;
- путь к исходному табелю;
- путь к файлу СКУД;
- список ненайденных ФИО;
- список неоднозначных ФИО;
- список ФИО с датами без записей СКУД;
- список сотрудников и дат, где встречался повторный вход/выход запрещен;
- список сотрудников и дат с иными проблемными сообщениями СКУД;
- количество заполненных ячеек;
- ошибки и предупреждения, не остановившие обработку.

## 11. Диагностическая подсветка при заполнении

Рекомендуемые цвета:

| Ситуация | Подсветка |
|---|---|
| Сотрудник найден и часы заполнены | Без изменения или светло-зелёная диагностика. |
| Сотрудник не найден в СКУД | Светло-красная / розовая. |
| Неоднозначное сопоставление ФИО | Оранжевая. |
| Повторный вход/выход запрещен | Дневную ячейку не выделять. Значение не менять. Примечание в Excel не добавлять. Сообщение фиксируется только в протоколе. |
| Запрещающее, ошибочное или служебное сообщение СКУД | Дневную ячейку не выделять. Значение не менять. Примечание в Excel не добавлять. Сообщение фиксируется только в протоколе. |
| Одна разрешенная запись СКУД за день, поставлено 2 часа | Светло-синяя или другой отдельный диагностический цвет. |
| Нет событий за день | Дневная ячейка пустая; ФИО может быть выделено диагностическим цветом. |
| Ошибка чтения даты или события | Красная / диагностическая подсветка. |

Цвета должны быть вынесены в константы, чтобы их можно было изменить.

## 12. Сравнение табелей

### 12.1. Назначение режима сравнения

Режим сравнения нужен для проверки различий между исходным табелем подрядчика и заполненным табелем, рассчитанным по данным СКУД.

### 12.2. Входные данные для сравнения

Сравнение выполняется между:

1. исходным табелем подрядчика;
2. заполненным табелем, созданным программой.

Файл сравнения создаётся на базе заполненного табеля, а не на базе исходного.

Это требуется для сохранения:

- рассчитанных часов;
- диагностических цветов;
- примечаний по ненайденным ФИО;
- примечаний по неоднозначным ФИО;
- примечаний по одной разрешённой записи или отсутствующим записям, если они были созданы при заполнении.

### 12.3. Логика сравнения

Программа сравнивает значения в дневных ячейках с часами за каждый день месяца.

Расчёт разницы:

```text
Разница = abs(ЗначениеИсходногоТабеля - ЗначениеЗаполненногоТабеля)
```

Сравнение выполняется для всех строк сотрудников и всех найденных дневных колонок. Количество дней месяца не задается вручную, а определяется по строке дат/дней в табеле.

Пустая ячейка считается равной `0`. Если обе ячейки пустые, сравнение можно пропустить. Если одна ячейка заполнена, а другая пустая, пустая считается `0` и сравнение выполняется по общим правилам.

Если значение ячейки не является числом и не может быть преобразовано в число, программа должна не падать, записать предупреждение в протокол сравнения и не изменять цвет/примечание этой ячейки.

### 12.4. Правила выделения результата сравнения

| Условие | Действие |
|---|---|
| Разница = 0 | Ячейка не выделяется. |
| 0 < Разница <= 1 | Дневная ячейка выделяется светло-зелёным цветом. К ячейке добавляется примечание: `Исходный табель: <X>. Заполненный табель: <Y>. Разница: <N> час(а/ов)`. |
| Разница > 1 | Дневная ячейка выделяется жёлтым цветом. К ячейке добавляется примечание: `Исходный табель: <X>. Заполненный табель: <Y>. Разница: <N> час(а/ов)`. |
| Обе ячейки пустые | Сравнение можно пропустить, ячейку не выделять. |
| Одна ячейка пустая | Пустая ячейка считается равной `0`, далее применяется обычное правило сравнения. |

### 12.5. Результат сравнения

Программа создаёт новый файл:

```text
<имя исходного табеля>_сравнение.xlsx
```

Файл сравнения создаётся на основе заполненного табеля. Затем поверх этой копии применяются результаты сравнения с исходным табелем.

В файле сравнения должны быть сохранены:

- структура табеля;
- форматирование;
- значения;
- цвета и примечания по ненайденным ФИО;
- цвета и примечания по неоднозначным ФИО;
- цвета и примечания, уже существующие в заполненном табеле и связанные с расчётом времени;
- выделение ячеек по результатам сравнения;
- примечания ко всем ячейкам с ненулевой разницей, включая допустимые расхождения до 1 часа включительно.

Перенос цвета и комментария к ненайденному или неоднозначному ФИО из заполненного файла в файл сравнения является обязательным требованием. Отдельных цветов и комментариев по проблемным сообщениям СКУД в заполненном файле быть не должно, поэтому перенос таких комментариев не требуется.

### 12.6. Протокол сравнения

Протокол сравнения должен содержать:

```text
ФИО
Дата
Значение в исходном табеле
Значение в заполненном табеле / по СКУД
Разница
Статус
Комментарий
```

Пример строки:

```text
Иванов Сергей Петрович; 03.06.2026; Табель=8; СКУД=10; Разница=2; Существенное расхождение
```

## 13. Требования к интерфейсу программы

В программе должны быть две основные операции:

1. **Заполнить табель по СКУД.**
2. **Сравнить табели.**

Для операции заполнения пользователь выбирает:

- файл табеля подрядчика;
- файл выгрузки СКУД.

Для операции сравнения пользователь выбирает:

- исходный табель подрядчика;
- заполненный табель подрядчика.

В интерфейсе должен отображаться журнал выполнения:

- начало обработки;
- выбранные файлы;
- чтение СКУД;
- поиск структуры табеля;
- анализ табеля;
- сопоставление ФИО;
- заполнение часов;
- обработка ошибок и предупреждений;
- путь к итоговому файлу.

Пример статистики заполнения:

```text
Обработка завершена.
Сотрудников в табеле: 35
Сопоставлено со СКУД: 31
Не найдено: 3
Неоднозначно: 1
Сотрудников с датами без записей СКУД: 5
Заполнено ячеек: 412
Ячеек требует ручной проверки: 8
Ошибок: 0
Файл: табель подрядчика_заполнен.xlsx
```

Пример статистики сравнения:

```text
Сравнение завершено.
Проверено сотрудников: 35
Проверено ячеек: 620
Существенных расхождений: 18
Допустимых расхождений: 7
Ошибок чтения: 0
Файл: табель подрядчика_сравнение.xlsx
```

## 14. Требования к обработке ошибок

Программа должна выдавать понятные сообщения в следующих случаях:

- не выбран файл табеля;
- не выбран файл СКУД;
- файл не найден;
- файл невозможно открыть;
- файл имеет неподдерживаемый формат;
- в табеле не найдена колонка `ФИО`;
- в табеле не найдена строка с датами или номерами дней;
- в табеле найден неоднозначный набор дневных колонок;
- в СКУД не найдена колонка `Дата записи`;
- в СКУД не найдена колонка `Персона`;
- в СКУД не найдена колонка `Сообщение`;
- в СКУД нет данных;
- не удалось определить месяц и год табеля при использовании номеров дней;
- ФИО не найдено в СКУД;
- ФИО найдено неоднозначно;
- не удалось сохранить итоговый файл.

Ошибки по отдельным ФИО или отдельным датам не должны останавливать всю обработку. Такие ошибки должны попадать в протокол.

Критические ошибки структуры файла должны останавливать выполнение.

Строку заголовков определять по колонке `ФИО`, строку дат — по Excel-датам или номерам дней месяца, строки сотрудников — как строки после строки дат. Разницу считать как абсолютное значение. При любой ненулевой разнице добавлять комментарий: допустимые расхождения до 1 часа включительно выделять светло-зелёным, расхождения больше 1 часа — жёлтым. |
| Протокол | Добавить подробный протокол заполнения и сравнения, включая предупреждения по ФИО, датам, проблемным сообщениям и нечисловым значениям. |

### 15.1. Excel COM Interop

### 15.2. Производительность

Программа должна минимизировать количество обращений к Excel по одной ячейке.

## 16. Логирование и протоколирование

### 16.1. Протокол сопоставления

Должен показывать:

- ФИО из табеля;
- ключ сопоставления;
- найденное ФИО в СКУД;
- статус:
  - найден по полному ФИО;
  - найден по краткому ключу;
  - не найден;
  - неоднозначно.

### 16.2. Протокол заполнения

Должен показывать:

- ФИО;
- дату;
- количество разрешенных событий СКУД;
- количество проблемных событий СКУД;
- первое разрешенное событие;
- последнее разрешенное событие;
- рассчитанные часы до округления;
- записанное значение;
- статус;
- комментарий/пояснение для протокола.

Примечание: текстовые пояснения в протоколе не означают обязательное добавление комментариев в Excel. Для проблемных/запрещающих сообщений СКУД комментарии в Excel не создаются.

### 16.3. Протокол ошибок

Должен показывать:

- тип ошибки;
- файл;
- лист;
- строку;
- колонку;
- исходное значение;
- текст ошибки.

### 16.4. Протокол сравнения

Должен показывать:

- ФИО;
- дату;
- значение исходного табеля;
- значение заполненного табеля;
- абсолютную разницу;
- статус расхождения.

## 17. Критерии приёмки

Работа считается выполненной, если выполняются следующие условия:

1. Пользователь может выбрать произвольные файлы табеля и СКУД.
2. Названия файлов не зашиты в коде.
3. Исходные файлы не перезаписываются.
4. Табель заполняется по ФИО из исходного табеля подрядчика.
5. Структура табеля определяется автоматически: строка заголовков находится по колонке `ФИО`, строка дат — по Excel-датам или номерам дней месяца, строки сотрудников — после строки дат.
6. Программа не зависит от фиксированных номеров строк.
7. Колонка ФИО определяется по заголовку `ФИО`.
8. Дневные колонки определяются по датам или номерам дней месяца.
9. Поддерживаются полноценные даты вида `01.02.2026` и номера дней месяца `1`, `2`, `3` и т.д.
10. Если Excel-ячейка хранит полноценную дату, но отображает только номер дня, программа обрабатывает её как дату.
11. Количество дней месяца определяется по самому табелю.
12. В СКУД обязательные колонки `Дата записи`, `Персона`, `Сообщение` ищутся по названиям.
13. Если в файле СКУД несколько листов, рабочий лист определяется по наличию обязательных колонок `Дата записи`, `Персона`, `Сообщение`. Листы без этих колонок игнорируются.
14. Сотрудники сопоставляются со СКУД по полному ФИО или по ключу `Фамилия + первая буква имени`.
15. Поиск только по фамилии не используется как достаточное условие сопоставления.
16. При отсутствии ФИО в СКУД строка не заполняется, ФИО выделяется цветом, добавляется примечание.
17. При неоднозначном совпадении строка не заполняется, ФИО выделяется цветом, добавляется примечание.
18. Для даты с одной разрешенной записью СКУД записывается `2` и ячейка выделяется отдельным цветом.
19. Для даты с двумя и более разрешенными записями часы считаются как разница между последним и первым временем минус 1 час.
20. Если после вычитания 1 часа результат меньше 0, в табель записывается `0`.
21. Округление выполняется по правилу: минутная часть `>= 50` минут — прибавить 1 час, иначе взять полные часы.
22. Сообщения `ПОВТОРНЫЙ вход запрещен/запрещён`, `ПОВТОРНЫЙ выход запрещен/запрещён`, `Выход запрещен/запрещён`, сообщения `Запрещено...` и иные проблемные сообщения не участвуют в расчёте часов, не выделяют дневную ячейку, не добавляют примечание в Excel и фиксируются только в протоколе обработки.
23. Создаётся файл `<табель>_заполнен.xlsx`.
24. Создаётся файл сравнения `<табель>_сравнение.xlsx`.
25. Файл сравнения создаётся на базе заполненного табеля.
26. При сравнении разница считается как абсолютное значение между исходным и заполненным табелем.
27. При сравнении ячейки с разницей больше 1 выделяются жёлтым и получают примечание.
28. При сравнении ячейки с разницей меньше 1, но больше 0, выделяются светло-зелёным и получают примечание.
29. При сравнении ячейки с разницей равной 1 также выделяются светло-зелёным и получают примечание как допустимое расхождение.
30. В файл сравнения переносятся цвета и комментарии по ненайденным и неоднозначным ФИО.
31. В файл сравнения не требуется переносить цвета и комментарии по проблемным сообщениям СКУД, потому что такие цвета и комментарии при заполнении не создаются.
32. Программа показывает журнал выполнения и итоговый отчёт.
33. Ошибки по отдельным ФИО и датам не останавливают обработку, а попадают в протокол.
34. После завершения обработки не остаются висящие процессы Excel.
35. Формируются протоколы или единый протокол с разделами.

## 18. Тестовые сценарии

### 18.1. Успешное заполнение по двум разрешенным событиям

Дано:

- табель содержит сотрудника `Иванов Сергей Петрович`;
- СКУД содержит `Иванов С.П.` или `Иванов Сергей Петрович`;
- за дату есть два разрешенных события: `09:00` и `18:10`.

Ожидаемый результат:

- сотрудник сопоставлен;
- расчёт: `18:10 - 09:00 - 1 час = 8 часов 10 минут`;
- `10 минут < 50 минут`, в табель записано `8`;
- строка отражена в протоколе как успешно обработанная.

### 18.2. Округление по порогу 50 минут

Дано:

- за дату есть два разрешенных события: `09:00` и `18:50`.

Ожидаемый результат:

- расчёт: `18:50 - 09:00 - 1 час = 8 часов 50 минут`;
- `50 минут >= 50 минут`, в табель записано `9`;
- в протоколе указаны первое и последнее разрешенные события.

### 18.3. Результат меньше нуля после вычитания 1 часа

Дано:

- за дату есть два разрешенных события: `09:00` и `09:30`.

Ожидаемый результат:

- расчёт: `09:30 - 09:00 - 1 час = -30 минут`;
- в табель записано `0`;
- ситуация отражена в протоколе.

### 18.4. Одно разрешенное событие СКУД

Дано:

- за день у сотрудника одно разрешенное событие `10:00`.

Ожидаемый результат:

- в табель записано `2`;
- ячейка выделена отдельным диагностическим цветом;
- в протоколе указано: `одна разрешенная запись СКУД, установлено 2 часа`.

### 18.5. Повторный вход запрещен

Дано:

- за дату у сотрудника есть сообщение `ПОВТОРНЫЙ вход запрещен`;
- разрешённых входов/выходов за эту дату нет.

Ожидаемый результат:

- сообщение не участвует в расчёте часов;
- дневная ячейка не выделяется;
- значение дневной ячейки не изменяется;
- комментарий в Excel не добавляется;
- запись добавлена только в протокол обработки.

### 18.5.1. Разрешённые и проблемные сообщения в один день

Дано:

- за дату у сотрудника есть два разрешённых события `09:00` и `18:00`;
- за эту же дату есть сообщение `Выход запрещен` или `Запрещено...`.

Ожидаемый результат:

- часы рассчитываются только по двум разрешённым событиям;
- проблемное сообщение не влияет на первую и последнюю разрешённую отметку;
- дневная ячейка не выделяется из-за проблемного сообщения;
- комментарий в Excel по проблемному сообщению не добавляется;
- проблемное сообщение отражается только в протоколе.

### 18.6. Сотрудник не найден

Дано:

- в табеле есть `Петров Пётр Иванович`;
- в СКУД нет соответствующей персоны.

Ожидаемый результат:

- строка не заполняется;
- ФИО подсвечивается;
- к ФИО добавлено примечание;
- в протоколе есть запись `не найден`.

### 18.7. Неоднозначное сопоставление

Дано:

- в табеле `Иванов С.`;
- в СКУД есть `Иванов Сергей` и `Иванов Семён`.

Ожидаемый результат:

- автоматическое заполнение не выполняется;
- строка подсвечивается как неоднозначная;
- к ФИО добавлено примечание со списком кандидатов;
- в протоколе перечислены оба кандидата.

### 18.8. Сравнение с расхождением больше 1 часа

Дано:

- в исходном табеле `8`;
- в заполненном табеле `10`.

Ожидаемый результат:

- абсолютная разница равна `2`;
- ячейка подсвечена жёлтым;
- комментарий: `Исходный табель: 8. Заполненный табель: 10. Разница: 2 час(а/ов)`;
- запись добавлена в протокол сравнения.

### 18.9. Сравнение с разницей ровно 1 час

Дано:

- в исходном табеле `8`;
- в заполненном табеле `9`.

Ожидаемый результат:

- абсолютная разница равна `1`;
- ячейка выделяется светло-зелёным;
- добавляется комментарий: `Исходный табель: 8. Заполненный табель: 9. Разница: 1 час(а/ов)`;
- запись добавляется в статистику как допустимое расхождение.

## 20. Рекомендуемый порядок доработки

### Этап 1. Безопасная подготовка

- убрать жёстко заданные имена файлов;
- добавить выбор файлов через диалоги;
- добавить единый протокол;
- добавить helper-методы нормализации ФИО и сообщений;
- добавить корректное освобождение COM-объектов.

### Этап 2. Определение структуры файлов

- реализовать поиск листа табеля;
- реализовать поиск строки заголовков по колонке `ФИО`;
- реализовать поиск строки дат;
- реализовать поиск дневных столбцов;
- реализовать поиск листа СКУД по обязательным колонкам.

### Этап 3. Чтение и нормализация СКУД

- читать `Дата записи`;
- читать `Персона`;
- читать `Сообщение`;
- нормализовать сообщения с учётом `е`/`ё`;
- фильтровать разрешенные события;
- выделять проблемные события;
- группировать события по сотруднику и дате.

### Этап 4. Сопоставление ФИО

- полное ФИО;
- краткий ключ `Фамилия + первая буква имени`;
- диагностика неоднозначностей;
- протокол сопоставления.

### Этап 5. Расчёт и заполнение

- правило одной разрешенной записи = `2` часа;
- правило двух и более разрешенных записей = первая/последняя отметка минус 1 час;
- защита от отрицательного результата;
- округление по порогу 50 минут;
- обработка проблемных сообщений только через протокол, без подсветки и комментариев в Excel;
- запись значений в копию табеля;
- пересчёт итогов при наличии итоговой колонки и отсутствии формулы.

### Этап 6. Сравнение

- сравнение исходного и заполненного табеля;
- создание файла сравнения на базе заполненного;
- перенос существующих диагностических цветов и комментариев из заполненного табеля;
- расчёт абсолютной разницы;
- подсветка расхождений по правилам `0 < разница <= 1` (светло-зелёный) и `> 1` (жёлтый);
- комментарии для всех ненулевых расхождений;
- протокол сравнения.

### Этап 7. Финальная диагностика

- статистика в интерфейсе;
- тестирование на реальных файлах;
- проверка, что Excel-процессы не остаются в памяти.

## 22. Итог

В результате доработки программа должна надёжно выполнять полный цикл:

```text
Табель подрядчика + Выгрузка СКУД
        ↓
Заполненный табель
        ↓
Сравнение с исходным табелем
        ↓
Файл сравнения + протоколы диагностики
```

Ключевые требования последней версии:

- не полагаться на жёсткие имена файлов;
- не полагаться только на фиксированный номер листа;
- не полагаться на фиксированные номера строк табеля;
- определять структуру табеля по заголовку `ФИО`, датам и строкам сотрудников;
- читать СКУД с обязательной колонкой `Сообщение`;
- фильтровать события СКУД по смыслу сообщения;
- учитывать `е`/`ё` при нормализации ФИО и сообщений;
