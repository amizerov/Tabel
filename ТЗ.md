# Техническое задание

## Обработка табеля подрядчика по данным СКУД и программа сравнения табелей

### 1. Назначение разработки

Необходимо разработать обработку для автоматического заполнения табеля подрядчика на основании выгрузки СКУД, а также отдельную функцию сравнения исходного табеля подрядчика с заполненным табелем.

Обработка должна работать с Excel-файлами формата `.xlsx`. Названия файлов могут отличаться, поэтому программа не должна быть жестко привязана к конкретным именам файлов.

---

## 2. Часть 1. Заполнение табеля подрядчика по данным СКУД

### 2.1. Запуск обработки

Пользователь запускает программу и выбирает два файла:

1. **Табель подрядчика**
   Пример: `табель подрядчика.xlsx`.

2. **Выгрузка СКУД**
   Пример: `СКУД СТРОЙМОНТАЖ 01.02.- 28.02.2026.xlsx`.

После выбора файлов пользователь нажимает кнопку запуска обработки.

---

### 2.2. Требования к входному файлу “Табель подрядчика”

Файл содержит табель подрядчика в формате Excel.

На примере файла:

* колонка **B** содержит ФИО сотрудников;
* строка **3** содержит заголовки;
* строка **4** содержит даты месяца;
* данные сотрудников начинаются со строки **5**;
* дневные ячейки находятся в диапазоне дат, например **D:AE**;
* колонка **AF** содержит итог часов.

Программа должна определять структуру не по фиксированным координатам, а по заголовкам и датам:

* колонка ФИО определяется по заголовку `ФИО`;
* дата-колонки определяются по строке с датами;
* количество дней месяца определяется по фактически найденным датам в табеле.

Исходный файл табеля не должен перезаписываться.

---

### 2.3. Требования к входному файлу “Выгрузка СКУД”

Файл содержит данные проходов сотрудников через СКУД.

Обязательные колонки:

* `Дата записи`;
* `Персона`.

На примере файла:

* `Дата записи` находится в колонке **A**;
* `Персона` находится в колонке **C**.

Программа должна искать эти колонки по названиям, а не по фиксированным номерам колонок.

Колонка `Дата записи` содержит дату и время прохода.
Колонка `Персона` содержит ФИО сотрудника.

---

## 3. Правила сопоставления ФИО

Для каждой строки табеля подрядчика программа берет значение из колонки `ФИО`.

Из ФИО формируется ключ поиска:

```text
Фамилия + первая буква имени
```

Пример:

```text
Удовиченко Александр Павлович → Удовиченко А
```

Аналогичный ключ формируется для значений из колонки `Персона` файла СКУД.

Перед сравнением ФИО необходимо нормализовать:

* убрать лишние пробелы;
* заменить неразрывные пробелы обычными;
* привести текст к одному регистру;
* заменить `ё` на `е`;
* игнорировать различия в количестве пробелов.

Рекомендуемый порядок поиска:

1. Сначала искать точное совпадение полного ФИО после нормализации.
2. Если точного совпадения нет — искать по ключу `Фамилия + первая буква имени`.
3. Если по ключу найден ровно один сотрудник — использовать его.
4. Если совпадений нет — считать ФИО не найденным.
5. Если по ключу найдено несколько сотрудников и точного совпадения нет — считать ФИО неоднозначным.

---

## 4. Действия при ненайденном или неоднозначном ФИО

Если ФИО из табеля не найдено в СКУД:

* часы по этому сотруднику не заполняются;
* ФИО в выходном файле выделяется цветом, например светло-красным;
* к ячейке ФИО добавляется примечание:

```text
ФИО не найдено в выгрузке СКУД.
Ключ поиска: <Фамилия И>
```

Если ФИО найдено неоднозначно:

* часы по этому сотруднику не заполняются;
* ФИО в выходном файле выделяется оранжевым цветом;
* к ячейке ФИО добавляется примечание:

```text
Неоднозначное совпадение в СКУД.
Ключ поиска: <Фамилия И>
Найденные варианты: ...
```

Исходный файл табеля подрядчика не изменяется.
Все выделения и примечания выполняются в выходном файле.

---

## 5. Алгоритм расчета часов по данным СКУД

После сопоставления сотрудника программа анализирует все записи СКУД по этому сотруднику.

Данные группируются:

```text
Сотрудник → Дата → Список проходов за дату
```

Для каждой даты выполняется расчет:

### 5.1. Если за дату есть две и более записи

Берется:

* самая ранняя запись за дату;
* самая поздняя запись за дату.

Далее рассчитывается длительность:

```text
Длительность = Последнее время - Первое время - 1 час
```

Результат округляется вверх до целого числа часов.

Формула:

```text
Часы = ОкруглениеВверх((ПоследнееВремя - ПервоеВремя) в часах - 1)
```

Если после вычитания 1 часа результат меньше 0, записывать 0.

Пример:

```text
Первый проход: 09:00
Последний проход: 18:10

18:10 - 09:00 = 9 часов 10 минут
9 часов 10 минут - 1 час = 8 часов 10 минут
Округление вверх = 9 часов
```

В табель записывается:

```text
9
```

---

### 5.2. Если за дату есть только одна запись

Если по сотруднику за конкретную дату найдена только одна запись СКУД, то в соответствующий день табеля записывается:

```text
2
```

---

### 5.3. Если за дату нет записей

Если по сотруднику за дату нет записей СКУД, ячейка табеля за этот день остается пустой.

---

## 6. Запись результата в табель

Программа создает новый файл на основе исходного табеля подрядчика.

Имя выходного файла формируется так:

```text
<имя исходного табеля>_заполнен.xlsx
```

Пример:

```text
табель подрядчика_заполнен.xlsx
```

В выходной файл копируются:

* вся структура исходного табеля;
* форматирование;
* объединенные ячейки;
* формулы;
* ширины колонок;
* высоты строк;
* стили ячеек.

Далее программа заполняет только ячейки дневных часов.

Для каждой строки сотрудника:

1. Берется ФИО из колонки `ФИО`.
2. Выполняется поиск сотрудника в СКУД.
3. Для каждой даты табеля рассчитываются часы.
4. Результат записывается в ячейку соответствующего дня.

Соответствие даты и колонки определяется по строке дат в табеле.

Например, если в строке дат указано:

```text
01.02.2026, 02.02.2026, 03.02.2026 ...
```

то результат за `02.02.2026` записывается в колонку, где находится дата `02.02.2026`.

---

## 7. Протокол обработки

После завершения обработки программа должна показать пользователю краткий отчет:

* сколько сотрудников найдено в табеле;
* сколько сотрудников успешно сопоставлено со СКУД;
* сколько ФИО не найдено;
* сколько ФИО найдено неоднозначно;
* сколько ячеек с часами заполнено;
* путь к созданному файлу.

Желательно также создать отдельный лист `Протокол` в выходном файле.

На листе `Протокол` указать:

* дату и время обработки;
* путь к исходному табелю;
* путь к файлу СКУД;
* список ненайденных ФИО;
* список неоднозначных ФИО;
* количество заполненных ячеек.

---

# 8. Часть 2. Программа сравнения табелей

## 8.1. Запуск сравнения

Пользователь запускает программу сравнения и выбирает два файла:

1. **Исходный табель подрядчика**
   Пример: `табель подрядчика.xlsx`.

2. **Обработанный табель**
   Пример: `табель подрядчика_заполнен.xlsx`.

После выбора файлов пользователь нажимает кнопку запуска сравнения.

---

## 8.2. Логика сравнения

Программа сравнивает значения в ячейках с часами за каждый день месяца.

Пример:

```text
D5 исходного табеля - D5 заполненного табеля
```

То есть:

```text
Разница = ЗначениеИсходногоТабеля - ЗначениеЗаполненногоТабеля
```

Сравнение выполняется для всех строк сотрудников и всех колонок с датами.

Количество дней месяца не задается вручную.
Программа определяет его по строке дат в табеле.

Например:

* для февраля может быть 28 или 29 дней;
* для апреля — 30 дней;
* для мая — 31 день.

---

## 8.3. Правила обработки результата сравнения

### 8.3.1. Если разница больше 1

Если:

```text
Разница > 1
```

то соответствующая ячейка выделяется желтым цветом.

К ячейке добавляется примечание:

```text
разница <N> час
```

Пример:

```text
разница 3 часа
```

Желательно в примечании также указывать исходные значения:

```text
Исходный табель: 8
Заполненный табель: 5
Разница: 3 часа
```

---

### 8.3.2. Если разница меньше 1

Если:

```text
Разница < 1
```

то соответствующая ячейка выделяется светло-зеленым цветом.

Примечание в этом случае не требуется.

---

### 8.3.3. Если разница равна 1

Если:

```text
Разница = 1
```

ячейка не выделяется.

---

### 8.3.4. Пустые ячейки

Пустая ячейка считается равной 0.

Если обе ячейки пустые, сравнение можно пропустить.

Если одна ячейка заполнена, а другая пустая, пустая считается 0 и сравнение выполняется по общим правилам.

---

## 8.4. Результат сравнения

Программа создает новый файл:

```text
<имя исходного табеля>_сравнение.xlsx
```

Пример:

```text
табель подрядчика_сравнение.xlsx
```

Исходные файлы не перезаписываются.

В файле сравнения должны быть сохранены:

* структура табеля;
* форматирование;
* значения;
* выделение ячеек по результатам сравнения;
* примечания к ячейкам с превышением разницы.

---

## 9. Требования к интерфейсу программы

В программе должны быть две основные операции:

1. **Заполнить табель по СКУД**
2. **Сравнить табели**

Для операции заполнения пользователь выбирает:

* файл табеля подрядчика;
* файл выгрузки СКУД.

Для операции сравнения пользователь выбирает:

* исходный табель подрядчика;
* заполненный табель подрядчика.

В интерфейсе должен отображаться журнал выполнения:

* начало обработки;
* выбранные файлы;
* чтение СКУД;
* анализ табеля;
* заполнение часов;
* обработка ошибок;
* путь к итоговому файлу.

---

## 10. Требования к обработке ошибок

Программа должна выдавать понятные сообщения в следующих случаях:

1. Не выбран файл табеля.
2. Не выбран файл СКУД.
3. Файл не найден.
4. Файл невозможно открыть.
5. В табеле не найдена колонка `ФИО`.
6. В табеле не найдена строка с датами.
7. В СКУД не найдена колонка `Дата записи`.
8. В СКУД не найдена колонка `Персона`.
9. В СКУД нет данных.
10. ФИО не найдено в СКУД.
11. ФИО найдено неоднозначно.
12. Не удалось сохранить итоговый файл.

Ошибки по отдельным ФИО не должны останавливать всю обработку.
Такие ошибки должны попадать в протокол.

Критические ошибки структуры файла должны останавливать выполнение.

---

## 11. Требования к доработке текущего C#-кода

В текущей реализации необходимо изменить следующие части:

### 11.1. Выбор файлов

Сейчас программа работает с папкой и жестко заданными именами:

```text
выгрузка_СКУД.xlsx
Табель_СКУД.xlsx
Табель_СКУД_заполнен.xlsx
```

Необходимо заменить это на выбор конкретных файлов через диалог открытия файла.

---

### 11.2. Логика заполнения табеля

Сейчас программа берет сотрудников из СКУД и записывает их в табель.

Нужно изменить алгоритм:

```text
Брать сотрудников из табеля подрядчика.
Для каждого ФИО из табеля искать соответствующую Персону в СКУД.
Заполнять часы в той же строке табеля.
```

---

### 11.3. Поиск колонок дней

Сейчас поиск дневных колонок выполняется по строке заголовка `ФИО`.

В предоставленном файле даты находятся на следующей строке, например:

```text
строка 3 — дни недели
строка 4 — даты
```

Необходимо искать дату-колонки по реальным Excel-датам, а не по числам в строке заголовка.

---

### 11.4. Расчет часов

Текущая логика одиночной отметки должна быть изменена.

Было:

```text
если одна запись — 8 часов
```

Должно быть:

```text
если одна запись — 2 часа
```

Для двух и более записей:

```text
ОкруглениеВверх(ПоследнееВремя - ПервоеВремя - 1 час)
```

---

### 11.5. Функция сравнения

Необходимо добавить отдельный режим сравнения двух табелей.

Режим должен:

* открыть исходный табель;
* открыть заполненный табель;
* найти строки сотрудников;
* найти колонки дат;
* сравнить ячейки часов;
* выделить ячейки цветом;
* добавить примечания при разнице больше 1;
* сохранить результат в отдельный файл.

---

## 12. Критерии приемки

Работа считается выполненной, если:

1. Пользователь может выбрать произвольные файлы табеля и СКУД.
2. Названия файлов не зашиты в коде.
3. Табель заполняется по ФИО из исходного табеля подрядчика.
4. Сотрудники сопоставляются со СКУД по ФИО или по ключу `Фамилия + первая буква имени`.
5. При отсутствии ФИО в СКУД строка не заполняется, ФИО выделяется цветом, добавляется примечание.
6. При неоднозначном совпадении строка не заполняется, ФИО выделяется цветом, добавляется примечание.
7. Для даты с одной записью СКУД записывается `2`.
8. Для даты с двумя и более записями часы считаются как разница между последним и первым временем минус 1 час, с округлением вверх.
9. Количество дней месяца определяется по самому табелю.
10. Исходные файлы не перезаписываются.
11. Создается файл `<табель>_заполнен.xlsx`.
12. Создается файл сравнения `<табель>_сравнение.xlsx`.
13. При сравнении ячейки с разницей больше 1 выделяются желтым и получают примечание.
14. При сравнении ячейки с разницей меньше 1 выделяются светло-зеленым.
15. Программа показывает журнал выполнения и итоговый отчет.
